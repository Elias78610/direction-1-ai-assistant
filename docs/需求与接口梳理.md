## 0. 全局约定（前后端契约，前端必须遵守）

| 约定项 | 规则 | 前端处理 |
| --- | --- | --- |
| 金额 | 一律为**整数「分」**（字段名 `amount_cents`），禁止浮点 | 展示时 ÷100 格式化为元（保留 2 位小数）；提交时 ×100 取整为分 |
| 日期 | ISO 格式 `YYYY-MM-DD`（消费发生日期，非录入时间）；时间戳用 ISO 8601 | 输入控件用 `st.date_input`，提交前 `strftime("%Y-%m-%d")` |
| 收支方向 | `direction` 字段：`expense`（支出）/ `income`（收入） | 记一笔时提供「支出/收入」切换 |
| 分类体系 | 8 个一级类目 + 其他：餐饮、交通、购物、居家日用、娱乐休闲、医疗健康、学习教育、人情往来、其他；支持二级类目（可选） | 下拉框从 `GET /api/categories` 动态拉取，不硬编码 |
| 数据来源 | `source` 字段：`text`（自然语言）/ `receipt`（小票OCR）/ `manual`（手动） | 按入口自动带上，不要求用户选择 |
| 解析置信度 | `confidence` ∈ [0,1] | 低于阈值（建议 0.7）在确认卡片上**黄色高亮提示复核** |
| 错误结构 | 建议统一 `{"detail": "..."}` 或 `{"code": "...", "message": "..."}` | 前端统一封装：先看 `detail`/`message` 字段，取不到则显示通用文案 |
| 分页 | 建议 `limit` / `offset`（备选 `page` / `page_size`，**与后端核对**） | 流水列表用「加载更多」或分页控件 |
| 后端地址 | 全局变量 `API_BASE_URL`，默认 `http://127.0.0.1:8000` | 见 `config.py`；运行时可在侧边栏高级设置覆盖 |

## 1. 功能点清单（7 大功能块）

### F1 整体布局：左侧固定侧边栏（仅概览）+ 主区域独立 Section 卡片

- **功能描述**：左侧固定侧边栏**只放全局概览**；主区域以独立 Section 卡片自上而下组织全部功能，**不用 tab/radio 导航**，一屏到底。
- **前端要点**：
  - 侧边栏（`st.sidebar`，固定，仅概览）：
    - 应用标题 + 当前后端地址
    - 流水概览卡片：本月收入 / 本月支出 / 结余（数据来自 `GET /api/stats/summary`）
    - 预算执行进度条（数据来自 `GET /api/budgets/status`）
    - 「高级设置」expander：显示并可覆盖后端地址（写入 `st.session_state`）
  - 主区域 Section 卡片**固定顺序**：
    ① 自然语言记账 → ② 小票 OCR 上传 → ③ 流水列表 → ④ 消费图表 → ⑤ 自然语言查账 → ⑥ 预算预警（含预算 banner 与预算设置）
  - 每个 Section 用卡片容器包裹，卡片间留白充足。
- **依赖接口**：`GET /health`、`GET /api/stats/summary`、`GET /api/budgets/status`

### F2 自然语言记账（输入 → 解析确认卡片 → 确认入库）

- **交互流程**：
  1. 用户在输入框输入一句话（如「昨天在星巴克喝咖啡花了 35」），支持「支出/收入」切换；
  2. 点「解析」→ 调 `POST /api/transactions/parse`；
  3. 返回结构化草稿 → 渲染**确认卡片**：金额 / 日期 / 分类 / 商户 / 备注 / 方向，**全部字段可编辑**；
  4. 点「确认入库」→ 调 `POST /api/transactions`（`source="text"`）；
  5. 解析失败 → `st.error` 友好提示 + **降级为手动录入表单**（`source="manual"`）。
- **前端要点**：
  - 金额编辑用 `st.number_input`（元为单位，提交时 ×100 转分）；
  - `confidence < 0.7` 时卡片标黄并提示「识别结果可能不准确，请核对」；
  - 分类下拉框来自 `GET /api/categories`；日期用 `st.date_input`；
  - 入库成功后：`st.success` + 清空表单 + 刷新侧边栏概览与预算 banner。
- **依赖接口**：`GET /api/categories`、`POST /api/transactions/parse`、`POST /api/transactions`

### F3 小票图片 OCR 上传（上传 → 识别 → 校对卡片 → 保存；失败降级）

- **交互流程**：
  1. `st.file_uploader` 上传图片（jpg/png/webp，限制大小如 ≤10MB）；
  2. 调 `POST /api/receipts/ocr`（multipart，字段 `file`）；
  3. 返回识别草稿 → 渲染**校对卡片**（同 F2，金额/日期/分类/商户可编辑），展示 OCR 原文折叠区；
  4. 点「确认保存」→ 调 `POST /api/transactions`（`source="receipt"`，带 `receipt_id`）；
  5. **失败降级**：OCR 接口失败或返回低置信度 → `st.warning` 引导「手动录入」路径（`source="manual"`，图片可作为说明留存）。
- **前端要点**：
  - 上传后立即 `st.spinner("正在识别小票…")`，OCR 超时需比普通接口长（见 config）；
  - 后端返回「疑似重复」（日期+金额+商户相同或图片 hash 重复）时，弹确认「疑似重复，是否仍要添加」；
  - 金额歧义（小票含合计/优惠/实付）：卡片上对不确定字段给出「需人工确认」标记；AA 场景提示「是否按人均记录」。
- **依赖接口**：`POST /api/receipts/ocr`、`POST /api/transactions`

### F4 流水列表 + 统计图表（查看/编辑/删除 + 饼图 + 柱状图 + 时间筛选）

- **功能描述**：
  - **流水列表**：查看（分页）、编辑（弹表单）、删除（二次确认）；支持时间范围/分类/方向筛选；
  - **消费分类饼图**：按所选时间范围统计支出分类占比；
  - **月度趋势柱状图**：近 6/12 个月支出趋势（月份连续、空月补 0）。
- **前端要点**：
  - 列表用 `st.dataframe` 或 `st.data_editor`（编辑场景优先考虑 `st.data_editor`，但需先确认后端字段可部分更新）；
  - 时间筛选快捷项：本月 / 上月 / 近 3 个月 / 自定义（`st.date_input` 范围选择），换算成 `start_date`/`end_date` 查询参数；
  - 饼图、柱状图可用 Plotly（`st.plotly_chart`）或 ECharts 组件，数据**只来自统计接口，前端不做金额计算**；
  - 金额列展示为元（÷100），并标注单位；
  - 删除需 `st.dialog`/确认按钮二次确认，防止误删。
- **依赖接口**：`GET /api/transactions`、`PUT /api/transactions/{id}`、`DELETE /api/transactions/{id}`、`GET /api/stats/category`、`GET /api/stats/monthly`

### F5 自然语言查账（对话输入 → 文字结果 + 统计表格）

- **交互流程**：
  1. 对话式输入（「这个月吃饭花了多少」「上月和这月餐饮对比」）；
  2. 调 `POST /api/query`（`{"question": "..."}`）；
  3. 返回 `answer`（文字回答）+ `table`（统计数据表格）→ 前端分别渲染：文字 + `st.dataframe`；
  4. 无法解析 / 超出记账范围 → 展示后端返回的友好拒绝文案。
- **前端要点**：
  - **数字全部来自后端返回的表格数据**，前端只负责展示，绝不自行计算金额；
  - 文字回答可用 `st.markdown` 渲染；表格按列名/行数据构造 DataFrame；
  - 建议保存最近几条问答作为简单对话历史展示（可选加分项）。
- **依赖接口**：`POST /api/query`

### F6 预算预警 Section：预算设置 + 预算 banner（80% 预警 / 100% 超支高亮）

- **功能描述**：
  - **预算设置**：设置某月（默认当前月）总预算 + 各分类预算；
  - **预算 banner**（位于预算预警 Section 顶部）：实时显示本月支出/预算比例：
    - < 80%：正常（绿色/中性）；
    - 80% ≤ 比例 < 100%：**黄色预警**「本月预算已使用 X%，请注意控制」；
    - ≥ 100%：**红色超支高亮**「本月已超支 X 元」。
- **前端要点**：
  - 设置表单（元为单位，提交 ×100）；提交后 `st.success` 并刷新 banner；
  - banner 比例来自 `GET /api/budgets/status`（后端计算 spent/ratio），前端**只做阈值判断与配色**；
  - 每次记账成功 / 删除流水后，主动刷新 banner 数据。
- **依赖接口**：`GET /api/budgets`、`PUT /api/budgets`、`GET /api/budgets/status`

### F7 通用容错（loading / 友好错误提示 / 后端地址全局变量）

- **功能描述**：
  - 所有接口调用包 `try/except` + `st.spinner`（或按钮态禁用）；
  - 错误提示分级：网络不可达（「无法连接后端服务，请确认服务已启动」）、超时、后端 4xx（展示 `detail`）、后端 5xx（「服务开小差了，请稍后重试」）；
  - 后端地址全局变量 `API_BASE_URL`（config.py）+ 运行时可在侧边栏覆盖；环境变量 `LEDGER_API_BASE_URL` 兜底；
  - 空数据边界：无流水/无预算/统计为空的友好占位文案。
- **前端要点**：
  - 封装统一的 `api_request()` 帮助函数（放在 `services/api_client.py`，由 Agent2/Agent3 实现），所有页面共用；
  - 请求超时按接口类型分级（普通 / LLM / OCR，见 config.py）。

### UI 设计规范（视觉实现细节由 Agent2 负责）

| 维度 | 规范 |
| --- | --- |
| 整体风格 | Modern SaaS 极简风、开发者工作台感；无复杂动画与花哨特效 |
| 配色 | 底色浅白中性 + 主色柔和蓝；**整体颜色 ≤ 3 种**（主色蓝 + 中性灰阶 + 预警色；预警色仅用于状态提示） |
| 布局 | 左侧固定侧边栏（仅概览）；主区域独立 Section 卡片自上而下排列，**不用 tab 导航**，卡片顺序固定 |
| 卡片/控件 | 卡片与输入框圆角、间距充足、重视留白 |
| 状态色 | 预算预警：≥80% 黄色、≥100% 红色超支高亮；正常态中性色 |
| 交互反馈 | 每个提交动作必带 loading（spinner/按钮禁用）；所有解析卡片（自然语言解析、OCR 校对）支持编辑修改后再确认 |
| 动效 | 禁用复杂动画，仅允许必要的 loading 指示 |

- 本文档只约定「结构 + 顺序 + 状态色 + 交互底线」，视觉细节由 Agent2 在 UI 开发阶段实现。
- Section 顺序唯一权威来源：自然语言记账 → 小票 OCR 上传 → 流水列表 → 消费图表 → 自然语言查账 → 预算预警。

## 3. 接口清单（推导值，**最终以后端 /docs 为准**）

### 3.0 通用错误约定

| HTTP 状态码 | 含义 | 响应体约定 | 前端处理 |
| --- | --- | --- | --- |
| 200 / 201 | 成功 | 见各接口出参 | 正常渲染 |
| 400 | 业务错误（无法解析、疑似重复等） | `{"detail": "..."}` 或 `{"code": "...", "message": "..."}` | 展示 `detail`，区分「疑似重复」引导确认 |
| 404 | 资源不存在 | 同上 | 提示记录可能已被删除，刷新列表 |
| 422 | Pydantic 校验失败 | FastAPI 默认 `{"detail": [{"loc": [...], "msg": "..."}]}` | 提示「输入格式有误」，定位到字段 |
| 500 | 服务器内部错误 | 同上 | 「服务开小差了，请稍后重试」 |
| 502 / 503 | 上游 LLM/VLM 服务不可用 | 同上 | 提示「AI 服务暂不可用」，走手动降级路径 |
| 网络异常 / 超时 | 前端本地判断 | — | 「无法连接后端服务，请确认服务已启动」 |

### 3.1 健康检查

| 项 | 内容 |
| --- | --- |
| 方法/路径 | `GET /health` |
| 入参 | 无 |
| 出参 | `200 {"status": "ok", "version": "0.1.0"}` |
| 用途 | 应用启动时探测后端连通性 |

### 3.2 分类

| 项 | 内容 |
| --- | --- |
| 方法/路径 | `GET /api/categories` |
| 入参 | 无 |
| 出参 | `200 {"categories": [{"id": 1, "name": "餐饮", "parent_id": null, "sort_order": 1}, ...]}` |
| 用途 | 记一笔/编辑/筛选/预算设置中的分类下拉与表格 |
| 注意 | `parent_id` 为空表示一级类目；若后端已含二级类目，前端按层级展示 |

### 3.3 自然语言记账解析

| 项 | 内容 |
| --- | --- |
| 方法/路径 | `POST /api/transactions/parse` |
| 入参 JSON | `{"text": "昨天在星巴克喝咖啡花了35", "direction": "expense"}` |
| 出参 JSON（200） | `{"draft": {"amount_cents": 3500, "occurred_at": "2026-11-22", "direction": "expense", "category_id": 1, "category_name": "餐饮", "merchant": "星巴克", "note": "喝咖啡", "confidence": 0.92}, "raw_input": "昨天在星巴克喝咖啡花了35"}` |
| 错误 | 400：文本为空 / 无法解析（前端降级手动录入） |
| 注意 | 若某字段不确定，约定返回 `null` 而非猜测；`category_id` 与 `category_name` 是否同时返回**与后端核对** |

### 3.4 流水创建（确认入库，三个来源统一走此接口）

| 项 | 内容 |
| --- | --- |
| 方法/路径 | `POST /api/transactions` |
| 入参 JSON | `{"amount_cents": 3500, "occurred_at": "2026-11-22", "direction": "expense", "category_id": 1, "merchant": "星巴克", "note": "喝咖啡", "source": "text", "raw_input": "昨天在星巴克喝咖啡花了35", "confidence": 0.92, "receipt_id": null}` |
| 出参 JSON（201） | `{"transaction": {"id": 123, "amount_cents": 3500, "occurred_at": "2026-11-22", "direction": "expense", "category_id": 1, "category_name": "餐饮", "merchant": "星巴克", "note": "喝咖啡", "source": "text", "created_at": "2026-11-23T16:55:00+08:00"}}` |
| 错误 | 400：疑似重复（前端弹「是否仍要添加」）；422：字段校验失败 |
| 注意 | OCR 来源时 `source="receipt"` 并带 `receipt_id`；手动来源 `source="manual"`；`receipt_id` 是否由后端单独确认接口管理**与后端核对** |

### 3.5 流水列表 / 编辑 / 删除

| 项 | 列表 | 编辑 | 删除 |
| --- | --- | --- | --- |
| 方法/路径 | `GET /api/transactions` | `PUT /api/transactions/{id}` | `DELETE /api/transactions/{id}` |
| 入参 | Query：`start_date`、`end_date`（YYYY-MM-DD，可选）、`category_id`（可选）、`direction`（可选）、`limit`、`offset` | 与创建入参同构（可部分更新，具体字段**与后端核对**） | 无 |
| 出参 | `200 {"transactions": [...], "total": 120, "limit": 20, "offset": 0}` | `200 {"transaction": {...}}` | `200 {"deleted": true, "id": 123}`（或 204，**与后端核对**） |
| 错误 | 422（参数格式错） | 404（不存在）/ 422 | 404（不存在） |

### 3.6 小票 OCR 识别

| 项 | 内容 |
| --- | --- |
| 方法/路径 | `POST /api/receipts/ocr` |
| 入参 | `multipart/form-data`，字段 `file`（图片文件，jpg/png/webp） |

## 4. 前端全局变量预留说明

由 `config.py`（项目根目录）承载，**全部带中文注释**，当前为占位版本，接口对接阶段可增补：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `API_BASE_URL` | `http://127.0.0.1:8000` | 后端根地址；优先级：`st.session_state["api_base_url"]`（运行时覆盖）> 环境变量 `LEDGER_API_BASE_URL` > 默认值 |
| `REQUEST_TIMEOUT` | `10` 秒 | 普通接口（列表/统计/预算/健康检查） |
| `LLM_REQUEST_TIMEOUT` | `60` 秒 | 解析/查账等 LLM 接口 |
| `OCR_REQUEST_TIMEOUT` | `120` 秒 | 小票 OCR（VLM 较慢） |
| `BUDGET_WARN_RATIO` | `0.8` | banner 黄色预警阈值 |
| `BUDGET_OVER_RATIO` | `1.0` | banner 红色超支阈值 |
| `PATH_*` 系列常量 | 见 3.x | 各接口路径；与后端核对后修改 |

约定：
- 所有页面**禁止硬编码 URL**，一律从 config 取；
- 请求封装为统一帮助函数（`services/api_client.py`，Agent2/Agent3 实现），统一处理超时、错误结构、JSON 解析；
- 金额换算工具函数（元↔分）放在 `utils.py`（Agent2 实现），全项目共用。

## 6. 边界与降级策略（前端必须兜住）

| 场景 | 前端行为 |
| --- | --- |
| 后端未启动 / 网络不可达 | 启动探测 `GET /health` 失败 → 首页显示「无法连接后端服务」引导页 |
| 解析/OCR 失败 | 自动切换手动录入表单（`source="manual"`），应用仍可用 |
| 低置信度草稿 | 卡片标黄 + 提示核对，仍允许用户确认（用户是最终把关人） |
| 疑似重复 | 弹确认「疑似重复，是否仍要添加」，确认后原样提交 |
| 无预算数据 | banner 显示「本月未设置预算」中性文案 |
| 无流水 / 统计为空 | 图表区显示「暂无数据」占位，不报错 |
| LLM/VLM 服务 5xx | 提示「AI 服务暂不可用」，记一笔/OCR 走手动降级 |
