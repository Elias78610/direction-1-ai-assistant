## 1. 对接总览

### 1.1 架构与唯一通信通道

```
sections/ + components/（页面层，零 HTTP 逻辑）
        │ 只调用函数，捕获 ApiError
        ▼
services/api_client.py（与后端通信的唯一通道）
        │ requests 统一封装：_request() → _check_response() → ApiError
        │ get_base_url() 运行时覆盖 > 环境变量 LEDGER_API_BASE_URL > config 默认值
        ▼
FastAPI 后端（默认 http://127.0.0.1:8000，路径常量见 config.py 第五节）
```

| 文件 | 职责 |
| --- | --- |
| `config.py` | `API_BASE_URL`、`DEMO_MODE`、三级超时（10/60/120s）、预警阈值、12 个 `PATH_*` 路径常量（改路径只改这里） |
| `services/api_client.py` | 15 个接口函数 + 统一请求封装（URL 拼接 / 超时分级 / 异常分类 / 422 定位 / 错误结构兼容） |
| `services/demo_data.py` | DEMO_MODE 内置示例数据（纯内存，无后端/LLM 逻辑，答辩演示兜底） |
| `utils.py` | `to_error_message()`：把 ApiError 按 kind 转友好文案（页面所有 try/except 统一调用） |
| `sections/`、`components/` | 页面与组件：只消费 api_client 函数，`st.spinner` + `st.error/st.warning`，不抛裸异常 |

### 1.2 启动命令（在真实终端执行）

```bash
# ① 安装依赖（版本已锁定，见 requirements.txt）
pip install -r requirements.txt

# ② 启动后端 FastAPI（按后端项目实际启动方式，示例）
uvicorn main:app --host 127.0.0.1 --port 8000
#    验证后端：浏览器打开 http://127.0.0.1:8000/docs 应能看到全部接口

# ③ 启动前端
streamlit run app.py
#    浏览器打开 Streamlit 提示的地址（默认 http://localhost:8501）

# ④ 无后端答辩演示兜底（二选一）
set LEDGER_DEMO_MODE=1 && streamlit run app.py      # Windows CMD
LEDGER_DEMO_MODE=1 streamlit run app.py             # macOS / Linux
#    或启动后在页面左侧「高级设置」勾选「演示模式」
```

### 1.3 DEMO_MODE 演示模式（默认 False）

- 开关优先级：侧边栏「高级设置」勾选 ＞ 环境变量 `LEDGER_DEMO_MODE=1` ＞ `config.DEMO_MODE` 常量；
- 开启后 15 个接口函数全部返回 `services/demo_data.py` 的内置示例数据（按当天日期动态生成近 6 个月流水），
  **不发任何真实 HTTP 请求**，增/删/改在内存中生效、页面各区块联动；
- 页头会显示蓝色提示条「当前为演示模式（DEMO）」；关闭后自动重新探测后端并恢复真实接口；
- 真实数据永远走 HTTP：演示模式只是兜底开关，不影响正常联调。

## 2. 统一请求封装与错误处理

### 2.1 封装分层（services/api_client.py）

| 函数 | 职责 |
| --- | --- |
| `get_base_url()` | 基地址：`st.session_state["api_base_url"]`（侧边栏覆盖）＞ 环境变量 ＞ `config.API_BASE_URL` |
| `is_demo_mode()` | 演示模式判断：侧边栏勾选 ＞ 环境变量 ＞ `config.DEMO_MODE` |
| `_url(path)` | 基地址 + `config.PATH_*` 拼完整 URL（页面禁止硬编码 URL） |
| `_request(method, path, timeout, **kwargs)` | 统一入口：`requests.request` + 超时分级 + 网络异常分类（见 2.2） |
| `_check_response(resp)` | 2xx → 解析 JSON（204 返回 `{}`）；非 2xx → 抛 `ApiError(kind="http")` |
| `_extract_error_detail(resp)` | 兼容 `{"detail": "..."}` / `{"code","message"}` / `{"error"}` / FastAPI 422 `{"detail":[{loc,msg}]}`（定位到字段） |

### 2.2 错误分类与友好文案映射

| 场景 | 捕获 | ApiError | 用户看到的文案 |
| --- | --- | --- | --- |
| 连接失败（拒绝/断网/DNS） | `requests.exceptions.ConnectionError` | `kind="network"` | 「无法连接后端服务，请确认服务已启动。」 |
| 其他请求异常 | `requests.exceptions.RequestException` | `kind="network"` | 同上 |
| 读超时 | `requests.exceptions.Timeout` | `kind="timeout"` | 「请求超时了，请稍后重试。」（`to_error_message` 统一） |
| 400 业务错误 | 状态码判断 | `kind="http"` | 后端 `detail` 原文（如「疑似重复」「无法解析」） |
| 404 | 状态码判断 | `kind="http"` | 后端 `detail` 原文（如「流水不存在」） |
| 422 校验失败 | 状态码判断 | `kind="http"` | 「输入格式有误：字段 xxx …」自动定位第一个字段 |
| 500 | 状态码判断 | `kind="http"` | 「服务开小差了，请稍后重试。」 |
| 502/503 LLM/VLM 不可用 | 状态码判断 | `kind="http"` | 「AI 服务暂不可用，请稍后重试，或改用手动录入。」 |

页面层约定（t2 已实现，t3 校验通过）：所有提交动作带 `st.spinner`；所有异常经
`utils.to_error_message(e)` 转友好文案后用 `st.error` / `st.warning` 展示，**任何页面不抛裸异常**。

### 2.3 超时分级

| 档位 | 秒数 | 适用接口 |
| --- | --- | --- |
| 普通 | 10（`REQUEST_TIMEOUT`） | health / categories / transactions CRUD / stats×3 / budgets×3 |
| LLM | 60（`LLM_REQUEST_TIMEOUT`） | parse（自然语言解析）、query（自然语言查账） |
| OCR | 120（`OCR_REQUEST_TIMEOUT`） | receipts/ocr（multipart 上传） |

## 3. 接口清单（15 个，前端实现与需后端配合点）

> 路径列给出 `config.py` 常量名；方法/入参/出参与 `docs/需求与接口梳理.md` 第 3 节一致。
> 若后端实际路由不同，改 `config.py` 的 `PATH_*` 即可，页面无感知。

### 3.1 健康检查

| 项 | 内容 |
| --- | --- |
| 函数 / 方法 / 路径 | `check_health()` ｜ GET `/health`（`PATH_HEALTH`）｜超时 10s |
| 入参 | 无 |
| 出参 | `200 {"status": "ok", "version": "0.1.0"}` |
| 前端使用 | app.py 启动探测；失败显示「无法连接后端服务」引导页 |
| **需后端配合** | 无需鉴权、响应 <1s；`version` 可选 |

### 3.2 分类列表

| 项 | 内容 |
| --- | --- |
| 函数 / 方法 / 路径 | `fetch_categories()` ｜ GET `/api/categories`（`PATH_CATEGORIES`）｜10s |
| 入参 | 无 |
| 出参 | `200 {"categories": [{"id", "name", "parent_id", "sort_order"}, ...]}` |
| 前端使用 | 记一笔/编辑/筛选/预算设置的下拉与表格（不硬编码） |
| **需后端配合** | 返回全部一级（及可选二级）类目；`parent_id` 为空表示一级；若含二级类目，前端暂平铺展示 |

### 3.3 自然语言记账解析

| 项 | 内容 |
| --- | --- |
| 函数 / 方法 / 路径 | `parse_transaction_text(text, direction)` ｜ POST `/api/transactions/parse`（`PATH_TRANSACTION_PARSE`）｜60s |
| 入参 JSON | `{"text": "...", "direction": "expense"}` |
| 出参 | `200 {"draft": {"amount_cents","occurred_at","direction","category_id","category_name","merchant","note","confidence"}, "raw_input": "..."}` |
| 错误 | 400 文本为空/无法解析 → 页面降级手动录入（source=manual） |
| **需后端配合** | `amount_cents` 整数分；`occurred_at` 为 YYYY-MM-DD；`direction` ∈ expense/income；`category_id` 必须在 /api/categories 中存在；`confidence` ∈ [0,1]；不确定字段返回 `null` 不要猜 |

### 3.4 流水创建（text / receipt / manual 三来源统一入口）

| 项 | 内容 |
| --- | --- |
| 函数 / 方法 / 路径 | `create_transaction(payload)` ｜ POST `/api/transactions`（`PATH_TRANSACTIONS`）｜10s |
| 入参 JSON | `{"amount_cents","occurred_at","direction","category_id","merchant","note","source","raw_input","confidence","receipt_id"}` |
| 出参 | `201 {"transaction": {"id","amount_cents","occurred_at","direction","category_id","category_name","merchant","note","source","created_at"}}` |
| 错误 | 400 疑似重复（页面弹「是否仍要添加」）；422 校验失败 |
| **需后端配合** | `source` ∈ text/receipt/manual；OCR 来源带 `receipt_id`、其余传 `null`；返回体必须回填 `id` 与 `category_name`（列表/图表渲染依赖） |

### 3.5 流水列表 / 编辑 / 删除

| 项 | 列表 | 编辑 | 删除 |
| --- | --- | --- | --- |
| 函数 | `fetch_transactions(start_date, end_date, category_id, direction, limit=200, offset=0)` | `update_transaction(tx_id, payload)` | `delete_transaction(tx_id)` |
| 方法 / 路径 | GET `/api/transactions` | PUT `/api/transactions/{id}`（`PATH_TRANSACTION_ITEM`） | DELETE `/api/transactions/{id}` |
| 入参 | Query：`start_date`、`end_date`（YYYY-MM-DD，可选）、`category_id`、`direction`、`limit`、`offset` | JSON 与创建同构（可部分更新） | 无 |
| 出参 | `200 {"transactions":[...], "total", "limit", "offset"}` | `200 {"transaction": {...}}` | `200 {"deleted": true, "id": 123}` 或 **204 无 body**（前端已兼容，统一返回 `{"deleted": True, "id": tx_id}`） |
| 错误 | 422 | 404 / 422 | 404 |
| **需后端配合** | 分页参数确认为 `limit/offset`（若为 `page/page_size` 需改 api_client）；每笔含 `id/amount_cents/occurred_at/direction/category_id/category_name/merchant/note/source`；按日期倒序 | 返回体与列表项同构（含 category_name） | 两种成功返回均兼容 |

### 3.6 小票 OCR 识别

| 项 | 内容 |
| --- | --- |
| 函数 / 方法 / 路径 | `ocr_receipt(file_bytes, filename)` ｜ POST `/api/receipts/ocr`（`PATH_RECEIPT_OCR`）｜120s |
| 入参 | multipart/form-data，字段名 **`file`**（jpg/png/webp，≤10MB；前端已预校验格式与大小） |
| 出参 | `200 {"receipt_id","draft":{...同 parse 草稿},"ocr_raw","warnings":[...],"duplicate_hint": bool}` |
| 错误 | 400 格式/大小不支持；500/503 → 页面降级手动录入 |
| **需后端配合** | 表单字段名必须为 `file`；`draft` 结构与 parse 一致；`warnings` 为字符串数组（可空）；`duplicate_hint=true` 时页面要求二次确认 |

### 3.7 统计：概览 / 分类占比 / 月度趋势

| 项 | 概览（侧边栏） | 分类占比（饼图） | 月度趋势（柱状图） |
| --- | --- | --- | --- |
| 函数 | `fetch_stats_summary(month)` | `fetch_stats_category(start_date, end_date, direction="expense")` | `fetch_stats_monthly(months=6, direction="expense")` |
| 方法 / 路径 | GET `/api/stats/summary` | GET `/api/stats/category` | GET `/api/stats/monthly` |
| 入参 Query | `month=YYYY-MM` | `start_date`、`end_date`（可选）、`direction=expense` | `months=6`、`direction=expense` |
| 出参 | `{"month","income_cents","expense_cents","balance_cents","transaction_count"}` | `{"total_cents","items":[{"category_id","category_name","amount_cents","ratio"}]}` | `{"items":[{"month","amount_cents","transaction_count"}]}` |
| **需后端配合** | 月份参数名确认为 `month`；金额整数分、balance 后端算 | `ratio` 后端算好（前端不算金额）；无数据 `items=[]` | 月份连续、空月补 0 由后端保证 |

### 3.8 自然语言查账

| 项 | 内容 |
| --- | --- |
| 函数 / 方法 / 路径 | `query_accounts(question)` ｜ POST `/api/query`（`PATH_QUERY`）｜60s |
| 入参 JSON | `{"question": "这个月吃饭花了多少"}` |
| 出参 | `200 {"answer":"文字回答","time_range":{"start","end"},"table":{"columns":[...],"rows":[[...]]}}` |
| 错误 | 400 无法解析/超出范围（`detail` 为友好拒绝文案，页面直接展示） |
| **需后端配合** | `table.columns` 与 `rows` 行列对齐；金额数字全部来自后端统计，前端只展示 |

### 3.9 预算查询 / 设置 / 状态

| 项 | 查询（表单回填+明细） | 设置（保存） | 状态（banner/侧边栏） |
| --- | --- | --- | --- |
| 函数 | `fetch_budgets(month)` | `save_budgets(payload)` | `fetch_budget_status(month)` |
| 方法 / 路径 | GET `/api/budgets?month=YYYY-MM` | PUT `/api/budgets` | GET `/api/budgets/status?month=YYYY-MM` |
| 入参 | Query：`month` | `{"month","total_budget_cents","category_budgets":[{"category_id","budget_cents"}]}` | Query：`month` |
| 出参 | `{"month","total_budget_cents","items":[{"category_id","category_name","budget_cents","spent_cents","ratio"}]}` | 同 GET 结构 | `{"month","total":{"budget_cents","spent_cents","ratio","level"}}` |
| **需后端配合** | 首行 `category_id=null` 为总预算；未设置分类 `budget_cents=0`；`spent/ratio` 后端算；预算为 0 时 `ratio=null` | PUT 为整月覆盖更新，重复 PUT 不产生重复记录；0=不设置 | `level` ∈ normal/warn/over（不返回时前端按 ratio 与 0.8/1.0 阈值自行判断）；未设置预算时 `budget_cents=0` |

> 💡 前端已修复一个边界：`sections/budget.py` 表单回填改为「仅 `None` 才用默认 3000 元」，
> 后端返回 `total_budget_cents=0`（未设置）时表单正确显示 0，不再误显示 3000。

## 4. 页面加载状态与异常兜底（已实现并校验）

- **启动探测**：app.py 每个会话一次 `GET /health`，失败显示引导页（含修改后端地址/勾选演示模式的指引），不再渲染功能卡片避免满屏报错；
- **提交动作**：解析/OCR/入库/保存/删除/查账/保存预算共 11 处 `st.spinner`（含启动探测 1 处、手动录入降级保存 2 处）；
- **错误分级**：所有页面调用经 `utils.to_error_message` → `st.error`/`st.warning`（侧边栏用 `st.caption/info`），无裸异常；
- **降级路径**：解析失败 → 手动录入表单（source=manual）；OCR 失败 → 黄条 + 手动表单；低置信度 → 卡片标黄；
- **空数据**：无流水/无图表数据/未设置预算均有占位文案；
- **侧边栏**：修改后端地址后自动重新探测连通性（不再需要手动刷新浏览器）。
